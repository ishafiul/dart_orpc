---
title: dart_orpc_http
description: HTTP adapter for unary RPC, REST/SSE, operations, and lifecycle, served on rust_http.
---

The HTTP adapter binds generated registries to an HTTP server. `listen` always serves on [`rust_http`](/dart-orpc/packages/rust-http), which implements the `dart:io` `HttpServer` API, so handlers, middleware, SSE, WebSockets and isolate workers use the familiar `dart:io` types. It serves `POST /rpc`, generated REST/SSE, docs/schema endpoints, and optional static/health/metrics endpoints. WebSocket upgrades use the separate WebSocket package on the same server.

Use generated `AppModule().buildRpcApp(...)` for ordinary apps. Low-level `RpcHttpApp` and `createRpcHttpHandler` support custom integration without requiring duplicate annotated route tables.

The [Application and HTTP Reference](/dart-orpc/reference/application) lists options/defaults and distinguishes generated helper options from lower-level runtime options. [Server Operations](/dart-orpc/guides/server-operations) explains policies, CORS, deadlines, response bodies, metrics, environment, isolates, and shutdown. [REST and SSE](/dart-orpc/guides/rest-and-sse) covers binding and terminal events.

HTTP RPC uses the framework's `{method, input}` envelope, not JSON-RPC 2.0.

The request path is built to allocate little: GET requests without a body skip the body reader, request IDs come from a per-app random prefix plus a counter, JSON is decoded from and encoded to bytes in one pass, and headers are copied once and shared with the RPC context. See [Benchmarks](/dart-orpc/benchmarks) for measured throughput.
