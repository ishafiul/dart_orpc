---
title: dart_orpc_luthor
description: Luthor schema validation bridge for typed input, output, and generated schemas.
---

This package re-exports Luthor and adapts its schema results to framework errors. With `@luthor` DTOs and `luthor_generator`, generated procedures automatically use schema validators. Freezed and json_serializable can supply immutable JSON contracts alongside them.

| Bridge | Behavior |
| --- | --- |
| `decodeRpcInputWithLuthor<T>` | Checks object input, validates, returns DTO; validation failure is BAD_REQUEST |
| `encodeRpcOutputWithLuthor<T>` | Serializes DTO, validates serialized value, returns JSON; failure is INTERNAL_ERROR |
| `encodeRpcOutputJsonWithLuthor<T>` | Validates serialized JSON without reconstructing a DTO |
| `LuthorSchemaValidator<T>` | Schema callback accepting JSON object |
| `LuthorReadOnlySchemaValidator<T>` | Callback contract that must not mutate input |
| `LuthorJsonSchemaValidator` | Read-only JSON validation callback |

Input decoder arguments are `rawInput`, `method`, required `validate`, and optional `validateReadOnly`. Output bridges take `output`, `method`, `toJson`, and their validator. Read-only callbacks allow the bridge to avoid defensive copies; custom callbacks must honor that contract.

Use `@HasMin(1)` for the non-empty title example, not invented `@LString`/`@LInt` annotations. See [DTOs and Validation](/dart-orpc/guides/procedures-and-dtos) and [Create an Application](/dart-orpc/guides/create-an-app) for complete supported source patterns.

Validation errors are formatted into `error.message`; the framework does not add a structured `details` array. Rich OpenAPI components derive from Luthor validators, so keep schemas and serialization in agreement.
