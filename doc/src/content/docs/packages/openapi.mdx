The current implementation emits **OpenAPI 3.0.3** from shared procedure metadata and build-time DTO schema metadata (`DtoSchemaRegistry` from `dart_orpc_core`). It does not depend on Luthor.

| API | Constructor/function arguments |
| --- | --- |
| `OpenApiDocumentOptions` | optional title/description; version defaults to `1.0.0`; servers defaults empty |
| `OpenApiServer` | required url, optional description; `.toJson()` |
| `createOpenApiDocument` | required `title` and `ProcedureMetadataRegistry procedures`. Optional `version`, `description`, `servers`, and `DtoSchemaRegistry schemas` |
| `createScalarHtml` | required title; openApiPath defaults to `/openapi.json` |

Generated apps supply registries automatically and serve a startup document snapshot. Current document paths represent explicit REST/SSE mappings, not individual RPC-only methods. SSE adds event schema/terminal metadata; bearer declarations add security metadata.

When upgrading a manual `createOpenApiDocument` call from the pre-Luthor 1.1 API, pass a `DtoSchemaRegistry` as `schemas`. The old `OpenApiSchemaComponent(validator: ...)` API was removed. Regenerate your application to update generated calls.

DTO enum fields use their serialized values in OpenAPI, including `@JsonValue` overrides. DTO schemas marked strict emit `additionalProperties: false`. A field annotated with `@WithCustomValidator` or `@WithSchemaCustomValidator` gets `x-dart-orpc-custom-validation: true`. The marker signals that the server enforces an additional rule.

Use [Scalar and OpenAPI](/dart-orpc/guides/scalar-openapi) for route configuration, auth, static export, CDN/offline behavior, and schema caveats.
